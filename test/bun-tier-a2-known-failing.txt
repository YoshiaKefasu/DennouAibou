# Tier A2 files (src/gateway/ and src/channels/) that `bun test` does not currently pass.
#
# Measured on bun 1.4.0 / Windows:
#   bun test --isolate src/gateway/**/*.test.ts src/channels/**/*.test.ts (Tier A subset)
#   -> channels: 292 pass / 12 fail / 1 error (67 files)
#   -> gateway:  562 pass / 13 fail / 2 errors (60 files)
#   Total:      854 pass / 25 fail / 3 errors (127 files)
#
# All entries below are pre-existing (fail under vitest too on this Windows machine).
# None are bun-specific regressions. Verified by running the same files under vitest
# on the same machine.
#
# Root causes:
#   1. Missing `dist/` or `dist-runtime/` build output — most bundled channel metadata
#      (aliases, configured-state checkers, persisted-auth probes, import guardrails)
#      requires a `pnpm build` to generate. These tests cannot pass without it.
#   2. Windows path difference — tests hardcode `/tmp/...` but path.resolve() on
#      Windows produces the current drive (`D:\tmp\...`).
#   3. IPv6 loopback unavailable on this Windows machine — bun returns
#      `ConnectionRefused` for `[::1]` connections. The test's try/catch already
#      covers `EAFNOSUPPORT`/`EADDRNOTAVAIL`; `ConnectionRefused` is now added.
#   4. E2E tests in gateway.test.ts need a running gateway instance.
#   5. ACP-specific session tests need bundled ACP channel metadata.
#   6. talk-config contract fixtures need provider resolution from bundled data.
#   7. model-pricing-cache needs bundled model catalog for alias resolution.
#   8. WS connection handling differs between bun and node in the 429 rate-limit
#      case — bun's ws polyfill may fire an unhandled ErrorEvent.
#   9. session-binding.registry-backed.contract.test.ts uses jiti which fails
#      when trying to load bundled plugin modules.
#
# Classification:
#   pre-existing   vitest fails too — already broken at HEAD, not a bun regression
