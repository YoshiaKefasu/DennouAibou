# 電脳サブエージェント（Dennou Subagent）プラグイン設計仕様書

## 1. 目的と概要

本仕様は、電脳相棒（DennouAibou）のコアにおいて、独立した専門サブエージェントを自律的に非同期実行・管理するための新プラグイン**「電脳サブエージェント（`extensions/dennou-subagent`）」**を定義する。

通話（電脳架電）に縛られることなく、通常のテキストチャット（Telegram、Discord、電脳屋敷）でも、通話中でも、**まったく同一の汎用サブエージェント機能**として自立して動作する。
メインエージェント（Kasou）のコンテキストを重たい作業ログで汚染させず、専門モデル・専門プロンプトによるタスク分担を実現する。

---

## 2. コア設計原則（KISS & 疎結合 & 安全弁）

1. **完全な独立プラグイン化（疎結合）**:
   - `extensions/dennou-subagent/` として独立。
   - `dennou.plugin.json` を持ち、他のプラグイン（電脳架電や電脳神経など）とは完全に切り離された単独機能として動作。
2. **ワークスペース定義の自動ロード (`workspace/agents/<name>.md`)**:
   - Kasou のワークスペース内 `workspace/agents/` に置かれた `.md` ファイルをスキャンして自動登録。
   - YAML フロントマターでモデル（DeepSeek, Kimi 等）や利用可能ツールを指定し、本文で独立したシステムプロンプトを定義。
3. **並列度制限の安全弁（暴走防止）**:
   - **カウント範囲**: マネージャー全体（セッション横断）で `running` 状態のサブエージェント数を数える。
   - **通常セッション（メインセッション等）からの起動**: 全体で最大 **7 体**（`MAX_CONCURRENT_SUBAGENTS_DEFAULT`）。
   - **通話セッション（`call:` 接頭辞）からの起動**: 音声通話の低遅延とリソース集中を守るため、全体で最大 **1 体**（`MAX_CONCURRENT_SUBAGENTS_CALL`）。他に実行中が 1 体でもあれば拒否する。
   - 上限到達時はわかりやすいエラーメッセージを返し、いずれかの完了を待つよう促す。
   - **検証順序**: 引数バリデーション（エージェント名の存在・`task` の非空・ワークスペース解決）を**通過した後**に並列度を判定する。不正な引数に対して上限エラーを返さない。
   - **タイムアウト監視（枠の永久占有防止）**: 実行が `defaultTimeoutMs`（既定 10 分）＋余裕（既定 30 秒）を超えたら強制失敗にし、枠を解放する。ランナーがハングしても 7 体枠が埋まったままにならない。
4. **メモ（memo）の非同期＆ツール除外原則**:
   - サブエージェントは独立した使い捨てセッションで動作するため、メインの能動記憶 `memo` は同期させない。
   - 二段構えで構造的に遮断する:
     1. **許可リスト段階**: 定義の `tools` から `memo` を除外する（`resolveSubagentTools`）。
     2. **実行時段階**: `before_tool_call` フックで、サブエージェントセッション（`dennou-subagent:` 接頭辞）からの `memo` 呼び出しを `block` する。これにより `tools` 未指定（全ツール許可）の定義でも `memo` は絶対に実行されない。
   - **重要な落とし穴（fail-open 防止）**: `runEmbeddedPiAgent` の `toolsAllow` は**空配列 `[]` を「指定なし＝全ツール許可」と同じに扱う**（`attempt.ts` の `length > 0` 判定）。したがって `tools: ["memo"]` のみのように全部除外されて空になるケースで `[]` を渡すと、memo を含む全ツール許可に化ける。実装では空になる場合に `disableTools: true`（ツール 0 件）を渡して fail-closed にする。
5. **非同期バックグラウンド実行 ＆ 2大ツール**:
   - `subagent(agent, task)`: タスクを非同期で開始し、即座に `agent_id` を返却（メインの会話をブロックしない）。
   - `get_subagent_result(agent_id)`: 進行中のステータス・最新ログ（途中経過）の確認、または完了済み結果の取得。**ブロッキング待機（wait）は行わず、常に即座に現在の状況を返す**（メインの会話を一切止めない）。
6. **完了時の自動通知報告（システム割り込み）**:
   - サブエージェントが完了した瞬間、その最終サマリーメッセージが**呼び出し元セッション**へシステム通知として届く（`sessionKey` が無い場合のみメインセッションへフォールバック。詳細は §6.1）。
   - Kasou は作業完了を自然に把握し、「Yosia！裏で頼まれていた〜〜の作業が終わったよ！」とユーザーへ報告できる。

## 3. ワークスペース定義の書式例 (`workspace/agents/executor.md`)

```markdown
---
name: executor
description: コード実装・ファイル編集・コマンド実行を担当する自律エージェント
model: cli-router/kios-deepseek-v4.1-flash
tools:
  - bash
  - read
  - edit
  - write
  - grep
---

あなたは電脳相棒 Kasou の右腕となる自律実行エージェント「Executor」です。
KISS 原則を徹底し、最小限の安全な変更でコード実装や検証を行います。
```

## 4. 提供する 2 つのツール仕様

### 4.1 `subagent` ツール

- **概要**: 指定したサブエージェントを非同期（バックグラウンド）で起動する。
- **引数**:
  - `agent` (string, 必須): 呼び出すエージェント名（例: `"executor"`）
  - `task` (string, 必須): サブエージェントへ依頼する具体的な指示
- **戻り値**:
  - `agent_id` (string): 起動したサブエージェントの一意な ID
  - `status` (string): `"running"`
  - `message` (string): `"サブエージェント executor を開始しました。進捗は get_subagent_result で確認できます。"`

### 4.2 `get_subagent_result` ツール

- **概要**: 実行中または完了したサブエージェントの状況・結果を非ブロッキングで即座に取得する（待機は行わない）。
- **引数**:
  - `agent_id` (string, 必須): 確認対象のサブエージェント ID
- **戻り値**:
  - `status`: `"running"` | `"completed"` | `"failed"`
  - `output`: 現在までの最新実行ログ、または最終完了メッセージ
  - `error`: エラー終了時のエラー詳細
- **運用原則**:
  - エージェントがポーリングや待機で会話をブロックすることを防ぐため、`wait` オプションは提供しない。
  - サブエージェントが完了するとシステム通知（完了報告）が届くため、通常は通知を待ってから結果を確認するか、必要時にのみ最新状況を照会する。

## 5. ライフサイクルと通知フロー

```text
[ユーザーからの指示（チャット or 通話）]
          │
          ▼
[Kasou: subagent(agent="executor", task="...")]
          │
          ├───▶ [電脳サブエージェントがバックグラウンド起動]
          │        ・並列度チェック（通常7体 / 通話中1体）
          │        ・指定されたモデル（例: DeepSeek）で自律実行
          │        ・ツール（bash, edit 等、memoは除外）を使いタスクを消化
          │
          ▼
[Kasou は待たずにそのまま通常通り会話を継続！]
（※ 進行中は必要に応じて get_subagent_result で即座に途中確認可能）
          │
          │ 【サブエージェント作業完了時】
          ▼
[自動通知報告がセッションへ注入]
   「[システム通知] サブエージェント executor が完了しました。結果: 〜〜」
          │
          ▼
[Kasou がユーザーへ自然に完了報告！]
   「Yosia、裏で頼まれていた作業が終わったよ！」
```

## 6. 電話（電脳架電）や他機能との関係

- 本プラグインは**完全に独立した汎用プラグイン**である。
- 通常のテキストチャット（Telegram, Discord, 電脳屋敷）でもそのまま使える。
- 通話セッション（電脳架電）から利用される場合も、通話中 Kasou はこの `subagent` ツールを叩いて裏で作業を走らせ、電脳屋敷の画面にはその最新アクションが 1 行で流れる。

### 6.1 通話セッションの判定基準（`call:` と `mainSessionKey` の関係）

本プラグインは「通話中かどうか」を **呼び出し元 `sessionKey` の接頭辞だけで判定する**（外部状態は見ない）。

| 項目                     | 契約                                                                                                                      |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| 通話セッションの判定     | `sessionKey` が `call:` で始まる（`CALL_SESSION_KEY_PREFIX`、判定関数 `isCallSessionKey`）                                |
| 通常セッション           | 上記以外のすべて（例: `agent:main:main`、`global`）                                                                       |
| 通話中の上限             | 全体で 1 体（`MAX_CONCURRENT_SUBAGENTS_CALL`）                                                                            |
| 完了通知の宛先           | 呼び出し元の `sessionKey`。`sessionKey` が無い場合のみ `mainSessionKey`（`resolveMainSessionKey`）へフォールバック        |
| メインセッションとの合体 | 電脳架電側の責務。本プラグインは通話終了時のセッション合体に関与せず、成果物は `get_subagent_result` でいつでも取得できる |

**矛盾の解消（旧記述の訂正）**: 以前の記述は「完了通知はメインセッションへ届く」「通話終了時にメインセッションへ合体」と読めたが、実装は次の通りである。

- 通知先は **呼び出し元セッション** であり、メインセッション固定ではない。通話中に `call:xxx` から起動した場合は `call:xxx` に通知イベントが積まれる（`notify.ts` の `sessionKey?.trim() || resolveMainSessionKey(config)`）。
- `mainSessionKey` は **呼び出し元キーが不明なときのフォールバック** にすぎない。
- 通話終了時の履歴合体は電脳架電の仕事であり、本プラグインは「サブエージェントの成果物を保持して `get_subagent_result` で返す」ところまでを責務とする。

**依存契約（重要）**: `call:` 接頭辞は電脳架電が通話セッションに付与する規約である。メインセッション（`agent:main:main`）から通話中に `subagent` を起動した場合、本プラグインは通話中と判定できず**通常セッション扱い（7 体上限）**になる。通話中の厳格制限（1 体）を効かせたい場合は、電脳架電側が `call:<callId>` 形式のセッションキーでツールを呼ぶ必要がある。
